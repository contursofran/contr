| D7 | 2026-10-29 | Rust code comments cite decisions of the Rust tracker (for example D10, D38). The port keeps the behavior that they describe and cites them as "Rust D10". | Those decisions stay valid. Their text is in the Rust issues and comments. |
| D8 | 2026-10-29 | Replaced by D27. No GitHub remote, issues, PRs or CI until parity. Slices are tracked outside the repository. Builders work on local branches in worktrees. | D9 | 2026-10-29 | `state.Visibility` follows the window through MyGo's public `Window` events: `IsVisible`, `OnShow`, `OnHide`, `OnMinimize`, `OnRestore`. A window that other windows cover sends no public event. For that case MyGo itself holds frames while nothing of the window shows (`platform.OccludableSurface`, `windowDidChangeOcclusionState:`): the view function, `Draw` and the work that `After` drives wait until some of it shows. Background work starts from `Visibility` and from view-driven `After` timers, and runs no loop or timer of its own while `Visible()` is false. | "No work while the window is hidden" (PORT-PLAN M4). MyGo v0.7.3 has no public occlusion event. If a covered window must also stop host sampling, that needs a MyGo change in a slice of its own. |
| D10 | 2026-10-29 | The terminal sends F1 to F12 only. MyGo v0.7.3 has no key codes past F12, so F13 to F20 do not reach herdr. The Rust app maps them. | Mac keyboards seldom have these keys. A MyGo change for them is not worth a slice of its own now. Revisit if a MyGo upgrade adds them. |
| D11 | 2026-10-29 | Host CPU and memory come from Mach calls (`host_statistics`, `host_statistics64`) loaded with purego, plus `hw.memsize` and `vm.pagesize` through `golang.org/x/sys/unix`. No cgo. Used memory is total minus (free + inactive + purgeable) pages. CPU % is the change in CPU ticks since the previous reading. `internal/host` holds the sampler. It is a timer state machine, not a loop, so a hidden window has no timer. | macOS has no sysctl for CPU load. purego is already in the module graph through MyGo, and `x/sys` is small and well known. The sampler needs no view state, so it lives outside `internal/app`. |
| D12 | 2026-10-29 | Agent rows have no per-row view as in Rust. MyGo builds the whole view on a redraw, so a row is a cached layer, the working icon draws its own turn (no build for it), and `AgentsList.Sync` reports which rows changed. | MyGo has no view that skips its build. The cache and the self-drawing icon keep paint and build work per row small. |
| D14 | 2026-10-29 | Go tests find panel parts by labels (`LabelBoardHeader`, `LabelTabReport`, and so on), not by Rust debug selectors. The Rust "-on" and "-picked" selector states become reads of the panel state (`Tab()`, the pick) plus `Selected(true)` on the shown tab for assistive technology. The tab labels end in "tab", so they do not clash with the card's `Report` button. | MyGo's Tester finds by text or label and has no debug selectors or state suffix. `Selected(true)` sets accent colours, so the segment sets its greyscale colours after it. |
| D15 | 2026-10-29 | The spaces column rescans git as Rust did. While the window is shown, a timer wakes every 10 s (one interval after the later of the last scan and the show) and redoes an old scan of the same cwds. The scan also runs when a pane has a new cwd, on a herdr change when the last scan is 10 s old or more, and when the window is shown with an old scan. The timer stops while the window is hidden and nothing else is scheduled, as the host sampler does (D11). The scan runs on a goroutine and lands through `Window.Update`; only the newest scan lands. | Parity with Rust: a `git switch` or a new worktree shows while herdr is idle. A hidden window has no timer and no scan, so AGENTS.md is kept. |
| D16 | 2026-10-29 | The board panel is a plain struct that the frame syncs (`Sync` from `syncBoard`), not an entity with observers. The report view and the outbox redraw through `Invalidate`. | MyGo has no observe or notify between views. The frame already knows when the board changes. |
| D17 | 2026-10-29 | The app version is the first line of `VERSION` in the repository root. `scripts/bundle.sh` reads it for `CFBundleShortVersionString`, `CFBundleVersion` and the zip name. The bundle script builds with `CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 go build -trimpath`, and writes to `dist/bundle` by default. `scripts/check.sh` runs `test-bundle.sh` and `test-install.sh`. | Go has no workspace manifest with a version, as Cargo has. | D18 | 2026-10-29 | A scroll event that is not momentum and comes 250 ms or more after the last scroll event drops the wheel remainder. The view compares event timestamps and uses no timer. | Rust clears the remainder on the touch phase `Started`. MyGo v0.7.3 gives no touch phase, only `Momentum`. The time gap marks a new gesture without a timer. |
| D19 | 2026-10-29 | `terminal.Starter` returns an `error`, although `endpoint.SpawnLink` cannot fail. The app's starter (`startHerdrTerminal` in `internal/app/frame.go`) always returns nil. A failed start sets the state to not running and is tried again only on a grid change, a click or a key, never on a timer. | Rust's thread spawn could fail, and its two failed-start tests port as they are. The error keeps that path testable. |
| D20 | 2026-10-29 | At startup `cmd/contr` registers `ApplePressAndHoldEnabled = NO` with `registerDefaults:` on the app's own `NSUserDefaults`, through purego's objc (no cgo). A held key repeats and shows no accent menu. The effect is the whole app, text fields of the board too. A value that the user set in the global defaults still wins. | MyGo v0.7.3 has no option for it. Rust turned the menu off for the terminal view only. `registerDefaults:` is in memory, writes no file and never changes the global defaults. |
| D21 | 2026-10-29 | View tests use an in-package fake `Link` (`fakeLink`) that records `endpoint.ClientMsg` values. | D23 | 2026-10-29 | The board panel's root column is focusable (no focus ring) and carries the panel keys as `OnShortcut`s: up, down, enter and 1 to 4. They run only when the focus is on the root or inside it. A click on non-focusable panel text (the summary) focuses the root. A click on a row button or a card button leaves the focus on that button, and the key still reaches the root's shortcut: a probe test shows that Enter after a click on a need row sends one answer and presses nothing twice. So the click handlers do not call `Handle.Focus`. On the Report tab the keys do nothing. | Rust focuses the panel on mouse down and binds the keys in a key context. MyGo has no key context, so the root's focus subtree is the context. The terminal keeps its keys, because it holds the focus (tested). |

| D38 | 2026-11-03 | `internal/hc` has a framed mode (#163): `DialFramed` sends `hello{generation:1,framed:true}`, then the connection carries frames, and `Attach` returns a `Stream`. Frame: channel uint32, kind uint8, length uint32 (little endian), then the payload; the limit is 16 MiB (`MaxPayload`). Channel 0 carries JSON-RPC (one message per DATA frame, requests too); an attach gets its own channel from the reply. Kinds: 0 DATA (terminal bytes; input from the viewer), 1 CREDIT (uint32 bytes consumed), 2 CLOSE (core: JSON `{reason}`; viewer: empty), 3 RESIZE (uint16 cols, uint16 rows; viewer to core, and core to an observer or a `resize_notifications` viewer), 4 FOCUS (1 or 0), 5 FACTS (JSON display facts), 6 AUTOMATIC_INPUT (terminal replies, not human input; unused). Credit: the core may send 256 KiB (`Window`) before the viewer acknowledges; the viewer sends CREDIT for the bytes that its consumer took, and more than a window of unacknowledged bytes is a stream error. First paint: DATA that starts with CAN and a soft reset (`ESC [ ! p`), mode resets, `ESC [ H ESC [ 2 J`, tab stops, then the screen, so a fresh emulator gives the right screen. `observe` attaches send no input and no size. How a second viewer with input affects the size of the owner's `hc attach` is not checked; S5 must check it. | Checked against a scratch core (`TestRealCoreFramedAttach`, `hccore` tag) and against the core's public wire description (read, not copied; see `NOTICE`). The layout lets S5 write the hc link; the stream is raw VT bytes, so the terminal view needs an emulator (S3). |
| D39 | 2026-11-03 | The terminal emulator for hc terminals (#163, D11) is the pure-Go library `charmbracelet/x/vt` v0.1.0, behind `internal/term/vt` (`New`, `Write`, `Screen(historyOffset)`, `Modes`, `Resize`, `Close`). Only that package imports it. It keeps 10000 lines of scrollback. The library answers queries (such as cursor position) through a pipe that blocks the parser when nobody reads it, so `New` takes a `respond` function and reads the pipe in a goroutine. `Close` closes that pipe itself, because the library's `Close` fails under `-race`. Compared with `hinshun/vt10x` on recorded streams (`ls` colors, a real vim start and exit, a hand-made Claude-like TUI) in `internal/term/vt/testdata`: vt10x has no scrollback, no bracketed paste (2004), no wide-glyph cells, and its last commit is from 2022; charm/x/vt has all of them and its last commit is from 2026-10. Speed on 3000 colored lines at 200×60: vt10x 6.6 ms, charm/x/vt 110 ms bare and 270 ms with 10000 lines of scrollback (about 5 ms per full screen of output). | Both are pure Go. Only charm/x/vt has scrollback, mode reporting and wide cells, which the view needs. It is slower, but a full screen of output costs about 5 ms. Remeasure with `BenchmarkFlood200x60` when the link (S5) is built. |
