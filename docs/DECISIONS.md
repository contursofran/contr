| D38 | 2026-11-03 | `internal/hc` has a framed mode (#163): `DialFramed` sends `hello{generation:1,framed:true}`, then the connection carries frames, and `Attach` returns a `Stream`. Frame: channel uint32, kind uint8, length uint32 (little endian), then the payload; the limit is 16 MiB (`MaxPayload`). Channel 0 carries JSON-RPC (one message per DATA frame, requests too); an attach gets its own channel from the reply. Kinds: 0 DATA (terminal bytes; input from the viewer), 1 CREDIT (uint32 bytes consumed), 2 CLOSE (core: JSON `{reason}`; viewer: empty), 3 RESIZE (uint16 cols, uint16 rows; viewer to core, and core to an observer or a `resize_notifications` viewer), 4 FOCUS (1 or 0), 5 FACTS (JSON display facts), 6 AUTOMATIC_INPUT (terminal replies, not human input; unused). Credit: the core may send 256 KiB (`Window`) before the viewer acknowledges; the viewer sends CREDIT for the bytes that its consumer took, and more than a window of unacknowledged bytes is a stream error. First paint: DATA that starts with CAN and a soft reset (`ESC [ ! p`), mode resets, `ESC [ H ESC [ 2 J`, tab stops, then the screen, so a fresh emulator gives the right screen. `observe` attaches send no input and no size. How a second viewer with input affects the size of the owner's `hc attach` is not checked; S5 must check it. | Checked against a scratch core (`TestRealCoreFramedAttach`, `hccore` tag) and against the core's public wire description (read, not copied; see `NOTICE`).
